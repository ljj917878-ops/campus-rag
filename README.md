# CampusRAG-Eval：带评测门禁的校园文档问答 RAG

面向校园规章问答的检索增强系统：从学生手册中检索相关条款，抽取原文句子组成答案，并附带章节与片段引用。系统不调用外部大模型，安装依赖后即可离线运行。配套一份固定 15 题评测集和可脚本化的质量门禁，用于检验检索与回答是否覆盖关键信息、是否忠于原文。

当前实现是可完整运行的抽取式原型，不是已上线的生产服务。内置文档《青禾大学学生手册》为演示用模拟材料，不代表任何真实院校规定。

## 功能范围

已实现：

- 加载内置示例手册，或上传一份或多份 `.txt` / `.md` 文档重建索引（自动按 UTF-8 或 GB18030 解码）
- 按段落优先切分文档，超长段再按字符窗口切分，并识别「第×章 / 附则」等章节标题
- 使用 TF-IDF 检索（jieba 分词 + 汉字 2-gram，余弦相似度），默认返回 4 条依据，界面可在 2–8 之间调整
- 从命中段落中抽取与问题最相关的句子（最多 4 句），答案末尾标注依据片段编号
- 相关度不足时明确提示「没有找到足够相关的依据」，而不是编造内容
- Streamlit 界面展示答案、引用依据和完整检索排序
- 运行日志写入 `logs/campus_rag.log`
- 固定 15 题评测脚本：输出分项分数，并以退出码作为门禁（通过为 0，未通过为 1，执行失败为 2）

当前未实现（请勿按已有功能对外表述）：

- 外部大模型生成式回答、向量数据库、稠密向量 / 混合检索
- PDF、Word 等非纯文本格式
- 多轮对话记忆、用户登录与权限
- 仓库内的 GitHub Actions 或其他 CI 配置文件（目前只提供可接入 CI 的评测脚本与退出码）

## 系统架构

```
文档（示例手册或上传的 .txt/.md）
        │
        ▼
  文本切分（段落优先；默认窗口 280 字，重叠 60 字）
        │
        ▼
  TF-IDF 索引（jieba 词 + 汉字 2-gram，sublinear TF，L2 归一化）
        │
问题 ──► 同一分析器向量化 ──► 余弦相似度 Top-K 检索
        │
        ├── 最高分 < 0.02  → 返回「依据不足」（status=no_evidence）
        └── 否则对命中段落分句，再用 TF-IDF 抽取至多 4 句
                │
                ▼
        答案 + 依据（chunk_id / 章节 / 原文片段 / 相似度）
                │
                ├── Streamlit 界面展示（app.py）
                └── evaluation.py 对 15 道固定题打分并执行门禁
```

核心模块：

| 文件 | 作用 |
| --- | --- |
| `rag_engine.py` | 切分、索引、检索、抽取式回答与引用结构 |
| `app.py` | Streamlit 前端 |
| `evaluation.py` | 15 道固定题、指标计算与门禁 |
| `data/campus_handbook.txt` | 内置示例手册（10 章 + 附则，切分后 15 个片段） |
| `requirements.txt` | `streamlit`、`scikit-learn`、`numpy`、`jieba` |
| `logs/` | 运行时生成，已从版本管理中忽略 |

检索侧为什么同时使用 jieba 和汉字 2-gram：纯分词遇到专有词或数字空格写法（如「3 个工作日」与「3个工作日」）时容易切分不一致；加上相邻二字组合，可以减轻这类误差。回答侧不做生成，只从检索到的原文句子里挑选并拼接，便于用忠实度指标检查「答案是否能在上下文中找到依据」。

## 如何运行

需要本机已安装 Python 3（建议 3.10 或更高版本）。

```bash
cd campus-rag
python -m venv .venv
source .venv/bin/activate          # Windows：.venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

按终端提示在浏览器打开本地地址，一般为 <http://localhost:8501>。

使用步骤：

1. 在左侧点击「使用示例校园手册」，或上传自己的 `.txt` / `.md` 后点击「用上传文件重建索引」。
2. 可调整「返回依据条数 top_k」（默认 4）。
3. 选择示例问题或自行输入，点击「提问」。
4. 查看答案、引用依据，必要时展开「查看全部检索结果」。

界面内置的示例问题包括宿舍熄灯与大门关闭时间、国家奖学金金额、校园卡补办与工本费、无故缺考处理等。评测集中的题目也可以直接用来手工抽查。


## 生成式回答（可选）

默认仍是抽取式，不需要密钥。若要启用生成式，复制 `.env.example` 为 `.env`，填写 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`（DeepSeek、通义兼容模式或本地 Ollama 均可），然后在界面左侧选择「生成式」。未配置或调用失败时自动退回抽取式。

## 评测门禁

```bash
python evaluation.py
```

可选参数：

```bash
python evaluation.py --top-k 4 --json eval_results.json
python evaluation.py --keyword-threshold 0.60 --faithfulness-threshold 0.70 \
  --retrieval-threshold 0.70 --overall-threshold 0.65
```

`--json` 会把每题的答案、分项分数、缺失关键词和引用编号写入指定文件。`eval_results.json` 已列入 `.gitignore`。

### 评测集

`evaluation.py` 中固化了 15 道题（Q01–Q15），覆盖入学报到与注册、旷课与缺考、奖学金、宿舍管理、图书馆借阅、校园卡补办、留校住宿、校医院门诊与急诊电话、社团发起条件、大型活动报备、成绩复核等。每题指定了必须在答案中出现的关键词（支持全部命中、任一命中、分组命中，以兼容「3 个工作日 / 3个工作日」这类写法），以及检索上下文中应出现的线索。

### 指标含义

| 指标 | 含义 | 默认门禁阈值 |
| --- | --- | --- |
| 关键词覆盖 `keyword_hit` | 答案是否覆盖该题预设的关键信息 | 平均 ≥ 0.60 |
| 忠实度 `faithfulness` | 答案句子能否在检索到的完整段落中找到依据（句级 8 字滑窗 + 分词重合，按 0.7 / 0.3 加权） | 平均 ≥ 0.70 |
| 检索命中 `retrieval_hit` | 检索上下文是否覆盖该题预设线索 | 平均 ≥ 0.70 |
| 相关性 `relevance` | `0.6 × 关键词 + 0.4 × 检索`，用于观察，不单独设门禁 | — |
| 综合分 `overall` | `0.4 × 关键词 + 0.35 × 忠实度 + 0.25 × 检索`；单题若回答出错则记 0 | 平均 ≥ 0.65 |

全部题目的上述四项平均分都达到阈值时，进程退出码为 0，否则为 1。评测过程本身异常退出时为 2。可以把该命令接到持续集成中作为质量门禁；本仓库尚未附带现成的 CI 配置文件。

## 已知限制

- 答案是抽取和拼接原文句子，不能改写、归纳或做超出原文的推理。
- 示例手册较短，切分后仅 15 个片段；默认 280 字窗口在个别超长段上仍可能从句子中间切断。
- 只支持纯文本，上传其他格式会被拒绝。
- 评测量表与题目是针对这份手册设计的，存在「出题即针对系统能力」的偏差；换手册后需要重写出题与关键词。
