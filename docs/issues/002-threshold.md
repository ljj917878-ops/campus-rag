## 现象

`min_score=0.02` 这个阈值形同虚设。实测：问一个与手册完全无关的问题（火锅相关的），最高得分 **0.0879**，仍然通过了门槛，返回 `status=ok` 并给出了一个不相干的答案。

## 影响

- 对无关问题不拒答，等于放任幻觉
- 用户会以为系统"知道"，实际是硬凑出来的答案
- 这是 RAG 系统最致命的失败模式：错得很有自信

## 原因分析

0.02 这个值是按"能通过所有正样本"倒推出来的，不是按相关性分布标定的。正样本得分普遍在 0.3 以上，负样本在 0.05~0.1 之间——门槛应该落在两者之间。

## 期望行为

- 按实际得分分布标定门槛（初步判断 0.15 左右）
- 低于门槛时返回明确的"未找到相关条款"，不要返回凑出来的句子
- 门槛值写进配置，并在 README 里说明依据

## 验收标准

- [ ] 新增 5 条负样本（与手册无关的问题），全部正确拒答
- [ ] 原有 15 条正样本召回不下降
- [ ] `evaluation.py` 输出拒答率指标

## 2026-11-14 补：20 个负例跑完，结论要改

`experiments/negative_probe.py` 拿 20 个手册外问题去打同一档参数（280/60/top-4），结果：

| 指标 | 数值 |
|---|---|
| 负例 top1 最高 | **0.2014**（「校园卡的支付密码忘了怎么办？」） |
| 负例 top1 中位 | 0.0906 |
| 正例 top1 最低 | **0.1852** |
| 0.02 门槛下的放行数 | **18 / 20** |

**负例最高分 0.2014 已经高于正例最低分 0.1852 —— 正负区间重叠，任何单一分数阈值都分不开。**

但换成看「top1 减 top2 的分差」就分得开：

- 负例分差最大 **0.1205**，正例分差最小 **0.1353**，中间有一条窄缝（≈0.128）
- 20 个负例里绝大多数 top2 紧跟 top1（说明没有一条真正命中，只是关键词碰巧重合）

所以修法不是「把 0.02 调到 0.15」，而是**换判定方式**：`top1 ≥ 门槛 且 (top1 − top2) ≥ 0.13`。样本只有 35 条，这仍是初步结论，扩充负例后应重算。

复现：`.venv\Scripts\python.exe experiments\negative_probe.py`
