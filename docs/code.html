split_into_chunks() rag_engine.py:195

把一整本手册切成一张张「小卡片」。为什么切？因为后面要找「最相关的那几段」，总不能每次把整本书塞进去。

def split_into_chunks(text: str, source: str, chunk_size: int = 280, overlap: int = 60) -> list[Chunk]:
    """按段落优先切分；长段落按句子边界打包，不切断句子。"""
函数定义。text 是手册全文，source 是来源路径，返回值是卡片列表。chunk_size=280 意思是「一张卡片最多 280 个字」，overlap=60 是「相邻卡片最多重叠 60 字」——只拿整条/整句去重叠，这份手册被切开的段里块尾那条都长于 60 字，所以实测 15 张卡片之间没有重叠。

_units_of() / _pack_sentences() rag_engine.py:124

这两个是 2026-11-14 加的帮手：先把段落拆成「不能切断的最小单位」，再把单位打包成卡片。切点因此只落在「条」与「条」之间、句号之后，不会再出现「…没收器具并视」这种半句开头。

「第 X 条」前面插一个切点。正则里的 (?=…) 是零宽断言：只标记位置、不吞掉文字，所以条文本身一个字都不会少。

def _units_of(para: str, chunk_size: int) -> list[str]:
    """把一段拆成「不被切断的最小单位」：优先条，条太长再按句子，句子还太长才按字符。

    这样保证切点只出现在条与条之间、句号之后，不会出现「…没收器具并视」这种半句。
    """
    units: list[str] = []
    for art in _ARTICLE_SPLIT.split(para):
        if not art.strip():
            continue
        if len(art) <= chunk_size:
            units.append(art)
            continue
        for sent in _SENTENCE_SPLIT.split(art):
            if not sent.strip():
                continue
            if len(sent) <= chunk_size:
                units.append(sent)
            else:  # 极端情况：单句超过块上限，只能硬切
                for off in range(0, len(sent), chunk_size):
                    units.append(sent[off : off + chunk_size])
    return units
拆单位，三层兜底：先按「条」拆（art 是一条）；条太长再按句子拆（sent 是一句）；句子还超过上限（极端情况）才按字符硬切。sent[off : off + chunk_size] 是切片：从第 off 个字起，取最多 chunk_size 个字。range(0, len(sent), chunk_size) 表示步长为 chunk_size，一段一段往前走。前两层能命中，就绝不切句。
156–179
    units = _units_of(para, chunk_size)
    if not units:
        return []

    pieces: list[list[str]] = []
    buf: list[str] = []
    size = 0
    for unit in units:
        if buf and size + len(unit) > chunk_size:
            pieces.append(buf)
            tail: list[str] = []
            tail_size = 0
            for back in reversed(buf):
                if tail_size + len(back) <= overlap:
                    tail.insert(0, back)
                    tail_size += len(back)
                else:
                    break
            buf = tail[:]
            size = tail_size
        buf.append(unit)
        size += len(unit)
    if buf:
        pieces.append(buf)
打包：buf 是当前这筐里的单位，size 是筐里已有的字数。单位依次往筐里放，放不下就封筐；封筐时用 reversed(buf) 从筐尾往回看，把最后几个整单位留作重叠。tail.insert(0, back) 插到重叠列表开头，这样顺序还是原来的从前到后。buf = tail[:] 是切片复制，得到一份新列表，后面改 buf 不会改到已经封存的筐。重叠也是整条/整句，所以边界两侧不会各剩半句。

"".join(group) 把筐里的单位拼成一段文字。每筐文本回到原段里找真实起点（para.find(text, cursor)），写进 start_char。out 里每一项是 (这块正文, 它在段内的起点)。界面上「回到原文第几个字」靠它。

_tokenize() / _jieba_analyzer() rag_engine.py:93

中文没有空格，不能像英文那样按空格拆词。这里先用 jieba 把句子切成词，再补上相邻两个字的组合（2-gram），专有名词偶尔切错时还能对上。_fit() 和后面抽句时都会用到它。

93–94
def _tokenize(text: str) -> list[str]:
    return [tok.strip() for tok in jieba.lcut(text) if tok.strip() and not tok.isspace()]
jieba.lcut(text) 把中文切成词列表。这是列表推导式：tok 是切出来的每一个词；tok.strip() 去掉首尾空白；if tok.strip() and not tok.isspace() 丢掉空词。返回值是词的列表。
97–104
def _jieba_analyzer(text: str) -> list[str]:
    tokens = _tokenize(text.lower())
    # 对中文再加上 2-gram，缓解专有词切分误差
    grams = []
    compact = re.sub(r"\s+", "", text.lower())
    for i in range(max(0, len(compact) - 1)):
        grams.append(compact[i : i + 2])
    return tokens + grams
先把原文转成小写再分词，得到 tokens。compact 是去掉所有空白后的原文。compact[i : i + 2] 是切片：从第 i 个字起取两个字，这就是 2-gram。i 从 0 走到倒数第二个字，所以每个相邻字对都会收到。最后 tokens + grams 拼在一起交给 TF-IDF：分词准的时候用词，切错的时候两个字的组合还能对上。

_fit() rag_engine.py:331

把所有卡片做成一张「词-卡片分数表」，也就是索引。这一步相当于给每张卡片做一份「关键词档案」。

这是列表推导式：c 是 chunk（卡片），c.text 是卡片正文，把所有卡片的正文收成列表 corpus，一行一张卡片。现在是 15 张。
333–338
        self._vectorizer = TfidfVectorizer(
            analyzer=_jieba_analyzer,
            min_df=1,
            sublinear_tf=True,
            norm="l2",
        )
创建 TF-IDF 计算器。TF-IDF 的意思是：一个词在这张卡片里出现得越多、在别的卡片里越少，分数就越高。analyzer 用 jieba 中文分词（因为中文词之间没空格），它还会额外加相邻两字的组合（2-gram），好处是专有词被切错也能补救，代价是词表变大、噪声变多；min_df=1 表示「只出现一次的词也保留」；sublinear_tf=True 表示词频改用对数，同一个词出现 10 次不会当成 10 倍重要；norm='l2' 把每行长度归一化，避免长卡片天然分数高。
339

核心：算出 15 行 × 1856 列的大表。每一格 = 某个词在某张卡片里有多重要。算完存起来，以后提问时重复用。
340

def _content_terms(question: str) -> list[str]:
    """问句里长度 ≥2、且不是疑问词的实词，去重保序。"""
    terms = [t for t in _tokenize(question.lower()) if len(t) >= 2 and t not in STOP_TERMS]
    return list(dict.fromkeys(terms))
这是列表推导式：t 是问句里的一个词；只留长度 ≥ 2、且不在停用词表里的。单个字（如「的」「了」）太容易误撞，所以丢掉。dict.fromkeys(terms) 去重但保持先出现的顺序，再转回列表。
89–91
def _matched_terms(question: str, chunk_text: str) -> int:
    ctx = re.sub(r"\s+", "", _normalize_whitespace(chunk_text)).lower()
    return sum(1 for t in _content_terms(question) if t in ctx)
ctx 是卡片正文：先整理空白，再去掉所有空格、转小写，方便直接用 t in ctx 判断词在不在原文里。sum(1 for t in ... if t in ctx) 是生成器表达式：每命中一个实词就计 1，最后求和，得到命中个数。ask() 里用这个数跟 TIER_HIGH=2、TIER_MEDIUM=1 比较。

def _best_sentence(question: str, text: str) -> str:
    """从块里挑与问句实词重合最多的一句原文；都不含实词就取第一句。"""
    terms = _content_terms(question)
    sentences = [s.strip() for s in _SENTENCE_SPLIT.split(text) if s.strip()]
    if not sentences:
        return text.strip()
    best, best_hit = sentences[0], -1
    for s in sentences:
        hit = sum(1 for t in terms if t in s.lower())
        if hit > best_hit:
            best, best_hit = s, hit
    return best
注意：这里的 s 是 sentence（句子），不是前面 retrieve / ask 里的 score（分数）。列表推导式把卡片按句号、问号、感叹号、换行切开，s 是每一句。best 先记下第一句，best_hit 先记 -1。然后逐句数实词命中个数 hit，只要比当前最好的还多，就更新 best。都没命中时 hit 都是 0，0 > -1，会落在第一句（和注释里写的「都不含实词就取第一句」一致）。t 是问句里的一个实词，t in s.lower() 表示这个词出现在这句里。

为什么要把手册切成 15 段，而不是整本塞进去？

整本塞进去有两个问题：一是太长，二是没法知道答案来自哪一段。切开之后才能「找出最相关的几段」，也才能标引用。

280 / 60 这两个数字分别管什么？

280 = 一张卡片最多多少字；60 = 相邻卡片最多重叠多少字，用来避免一句正好被切在边界上。现在不是按固定步长 220 个字去滑动硬切，而是先按「条」和句子边界打包，重叠也只发生在完整的单位上。这份手册里块尾那条都长于 60 字，放不进重叠额度，实测 15 张卡片共 2647 字符、彼此没有重叠（12 段正文合计 2650）。

什么是「向量」？用这个项目解释。

就是「每个词有多重要」的一串分数。15 张卡片 × 1856 个词，每张卡片就是一行 1856 个数字。

为什么检索用 transform，建索引用 fit_transform？

建索引时要「学」出词表，所以用 fit_transform；提问时必须用同一套词表，只能 transform，否则两边的词对不上，分数就没意义。

「宿舍几点熄灯」只返回 3 条，不是 top_k=4 吗？

top_k 是上限。第 4 名分数是 0，被 retrieve() 里的 `if scores[i] > 0` 过滤掉了。

如果只让你改一处，让它更可靠，你改哪儿？

改切段：按句子/段落边界切，保证每张卡片从完整句子开始。这一处同时修好「半句开头」和一部分「答非所问」。
